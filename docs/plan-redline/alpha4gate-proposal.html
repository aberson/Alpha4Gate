Why this shape

Thirteen promotions, and no fixed opponent to show they helped.

Every promotion only had to beat its own parent, in a Protoss mirror on Simple64, by a simple majority of 5–9 games. A no-better candidate passes that half the time. The code that won was then deleted and rewritten from its description before shipping. Against VeryHard, v13 won 4 of 10 games in October and v0 won 2 of 5 in April, about the same rate.

Agent defaults

Defaults worth your eyes. Reference by ID to tweak.

RD1

Review blockerAs written, the scoreboard worker lives in src/orchestrator/scoreboard_worker.py (ES.2).

Why: I put it next to scoreboard.py. But it must import bots.<v>, and CLAUDE.md forbids that from src/orchestrator/ because it triggers a MetaPathFinder loop.

Tweak (recommended): move it to scripts/scoreboard_worker.py, launched by path, and add a test that keeps src/orchestrator/ free of bots.* imports.

RD2

Needs inputAs written, ES.7–ES.10 declare no dependency on the pending EH steps, although they all edit scripts/evolve.py.

Why: I wrote them as independent slices. In practice that invites merge conflicts and stale line anchors.

Tweak (recommended): land EH.3, EH.6, EH.7 and EH.8 first, then ES.6–ES.10, then EI.1–EI.6. ES.10 overlaps EI.4’s proposer evidence.

RD3

Needs inputAs written, the panel rollback is only seen if a real regression happens to occur during ES.12 or ES.13.

Why: the smoke tests the wiring, but a gate that never fires live is unproven.

Tweak (recommended): ES.12 injects a known-weak candidate (scripts/evolve_inject_one.py) and watches the rollback fire.

RD4

A stage passes on its point estimate plus a per-race floor; Wilson intervals are reported beside it.

Why: requiring the Wilson lower bound to clear 60% would need far more than 60 games. A 60% result over 60 games has a lower bound near 47%.

Tweak: require the lower bound to clear the target, and accept larger stage samples.

RD5

Stage 1 and later use 20 games per race (60 games, about 2.5 hours).

Why: twice the Stage 0 sample, for verdicts that decide what counts as progress.

Tweak: 10 for speed, or 30 for tighter verdicts.

RD6

Calibration runs before Stage 0. v13 must win at least 8 of 9 at Easy and at most 1 of 9 at CheatInsane, or the run stops.

Why: it proves the scoreboard can tell a sure win from a sure loss before its numbers are trusted.

Tweak: the thresholds, or a different known-bad opponent.

RD7

Frozen versions are not edited. The scoreboard builds each bot with that version’s own code, adding only the opponent race.

Why: the score has to describe the real version, not a re-implementation of it.

Tweak: none recommended, because scoring the real artifact is the point of the phase.

RD8

The built-in AI uses its default random build, and games are not seeded.

Why: run_bot has no build or seed parameter, so a “sealed schedule” fixes the order of matchups, not identical games.

Tweak: add a pinned build parameter (touches each version’s call path through the worker).

RD9

The panel is 12 games (4 per race) at the current stage’s difficulty. The incumbent’s results are reused rather than replayed.

Why: enough to catch a clear drop without halving the generations per night.

Tweak: 18 or 24 games, for fewer wrong rollbacks and slower evolution.

RD10

The new evolve flags (--promote-scored, --ai-panel, --panel-gate) default off and are switched on in ES.12 and ES.13.

Why: project convention keeps a bare evolve.py run byte-identical.

Tweak: make them the defaults once ES.13 has run.

RD11

The self-play fitness bar stays a simple majority during Phase ES.

Why: the panel guards quality, and ES.13 records the real pass rate to decide on later.

Tweak: require 4 of 5 now (the judging investigation’s top pick).

RD12

Regression against older ancestors is checked by stage scoreboards, not by extra games at every promotion.

Why: lower game cost per generation.

Tweak: add ancestor games to each promotion.

RD13

When two winning changes touch the same files, the later one is benched for the next generation and never rewritten.

Why: rewriting is exactly how untested code shipped before.

Tweak: cap each promotion at one winner.

RD14

The launcher runs evolve inside WSL in a visible console, and closing that console stops the run.

Why: it keeps today’s stop gesture and avoids the known WSL backgrounding trap.

Tweak: run in the background with a separate stop command.

RD15

evolve --viewer is deprecated with a warning, not removed.

Why: the smallest change that moves runs headless; removal can follow once the new viewer exists.

Tweak: remove the viewer code now.

RD16

Champion-challenge games are played on Simple64 only, 10 per opponent. The repoint uses a one-line Python call plus a commit.

Why: reuses the existing head-to-head tool and pointer helper with no new code.

Tweak: rotate maps, or add a scoreboard repoint command.

RD17

The scoreboard plays one game at a time by default (--concurrency 1).

Why: safe on memory. Four parallel games on Linux were validated in April and remain available.

Tweak: default to 2–4 in WSL.

RD18

Plan-review’s other gaps stay as review findings for plan-wrap and build time: hang limits, a single writer for result rows, a scoreboard run lock, argument quoting, outcome tokens shared with the dashboard, a WSL Claude login check, file lists, placeholders and retention.

Why: none of them needs a product decision.

Tweak: fold them into the plan now, before plan-wrap.

RD19

ES.11 reviews at least 12 of the champion’s losses, 4 per race.

Why: enough to see repeating patterns in each matchup.

Tweak: a different count, or review every loss when there are fewer than 12.

Risks

What could bite, and the built-in answer.

Linux replays (SC2 4.10) may not open in the Windows client (build 98310).

ES.1 tests one. If it fails, ES.11 replays the matchup live on Windows.

Scoreboard numbers come from SC2 4.10 and can’t be compared with April’s Windows results.

Every report states the substrate and build.

WSL setup has drifted since April.

ES.1 checks it before any long run.

Closing the console could leave Linux SC2 processes behind.

ES.12 checks with pgrep; any fix lands before ES.13.

The run lock mixes Windows and Linux process IDs.

A decision note on EH.7: the lock records which platform wrote it.

10 games per race gives wide intervals at Stage 0.

The champion challenge settles close calls; Stage 1 uses 20 per race.

The panel adds 12 games per promotion.

Incumbent results are cached, and the concurrency option is available.
