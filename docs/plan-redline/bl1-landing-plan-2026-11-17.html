Summary and recommendation

Recommendation: land through a pull request from a short-lived landing branch. Make it a merge commit (not squash, not rebase), then tag the merge commit master-plan/phase-ev/landed. This puts all 136 phase-ev commits on master with their SHAs unchanged, so they count on your contribution graph. It also gives the work its first Linux CI run before it lands.
  • The merge is not automatic. README.md conflicts in 4 hunks. Three are mechanical. One needs a wording choice: master corrected an overstated screenshot caption, and phase-ev still has the old text. Keep master's honest caption.
  • CI has never run on phase-ev. Both workflows trigger only on pushes to master and on pull requests. Master's own CI has failed since July on a single Python 3.12 test. Phase-ev already contains that fix (cherry-picks of open PRs #303 and #304), so landing should turn master green.
  • Nothing unwanted lands. The preserved Jev candidates are separate branches or uncommitted files, and none of them merges with phase-ev. The production bot pointer stays v13. The frozen trees bots/v0 to v12 change only in documentation-path strings.
  • Timing (decision D2): land before any EVO_AUTO run, while no lane is mid-build on phase-ev.

The earlier landing note proposed master-plan/ev/final, but this landing is no longer "Phase EV final": EV.4 and EV.5 moved into Phase VW, and the branch also carries EH, part of ES, Jev and the documentation migration.

Proposed: an annotated tag master-plan/phase-ev/landed on the merge commit on master (as phases 0, 2 and 4 tag their merge commits). Rollback

  • Before the merge: close the PR and delete land/phase-ev-2026-11-17. Nothing on master changed.
  • After the merge: run git revert -m 1 <merge-sha> through a PR, never a force-push to master. Note that re-landing later needs a revert of that revert first. Delete the tag only if the revert is final: git push origin :refs/tags/master-plan/phase-ev/landed.
  • Never rewrite master's or phase-ev's history to roll back. Too many issue comments, handoffs and plan lines cite these SHAs.

What only you can decide

  1. Authorize the landing and its timing. D2 says before any EVO_AUTO run, and lane evolve's build run is complete.
  2. PR path (recommended) or a local --no-ff merge. The PR publishes a landing branch and a PR; the local path lands without CI.
  3. README hunk 2 wording. Recommended: keep master's corrected caption.
  4. Tag name: master-plan/phase-ev/landed (recommended) or master-plan/bl1/landed.
  5. Mainline after landing. Either (a) work on master from now on and keep master-plan/phase-ev frozen until its gates close, or (b) keep working on phase-ev and land again later. Option (a) keeps your graph current without repeat landings. EVO_AUTO commits go to whichever branch is checked out, so choose before the next evolve run.
  6. Home paths in history: accept them (recommended; already public, and landing adds no exposure) or ask for a history rewrite (not recommended).
